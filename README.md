## 三网优化在实测里是什么样：官方口径与第三方数据的差距

官方对延迟的说法是中国大陆 RTT 低于 50ms，DDoS 防护最高 600Gbps 清洗能力。第三方单次实测的数字比这个保守，而且三家运营商的表现并不一致。

2025 年 12 月 23 日对 SIN.Pulse.Mini 的一次测速记录：新加坡本地 984.70Mbps 上传、942.26Mbps 下载、延迟 1.19ms；中国香港 45.00ms；联通上海 5G 102.37ms；电信镇江 5G 77.56ms；电信浙江 71.12ms；移动苏州 256.52ms，且该节点下载只有 0.31Mbps。

这组数据说明两件事。端口带宽确实跑得起来，新加坡本地接近千兆；「三网优化」描述的是路由层面有没有优化，并不能保证每条线每次测试都理想。电信方向落在 70ms 级别，比官方标称的 50ms 高，但仍在可用范围；移动方向那次测试的偏差就比较明显了。

单次测速受测试节点、时段和临时拥塞影响，不能当产品定论。但对移动用户占比较高的业务来说，这一条值得作为决策参考，别只看「三网优化」四个字就默认三家体验一致。

## 按使用场景选档：哪一档是多余的，哪一档不能省

选档的判断标准其实很简单：内存和流量哪个先卡住，就补哪个。五档里有三档对大多数人来说是过剩的，真正的常用区只有前两档。

**Nano（$29，2 核 2G / 500GB）**：适合单一轻负载场景——轻量 API 端点、代理节点、监控 agent、个人 WireGuard。500GB 流量是硬约束，跑起真实带宽很快就顶到上限。2GB 内存装完 Linux 系统本身要占掉五六百 MB，留给应用的空间大概 1.4GB，稍微压一下就 OOM。

**Mini（$49，2 核 4G / 1TB）**：绝大多数人的落点。4GB 内存能舒服地跑小型 WordPress + MySQL、低流量电商前端、Discord 或游戏服后端，或者几个容器的 Docker 主机。不确定选哪档时，从这档开始的试错成本最低。

**Air（$89，4 核 8G / 2TB）**：从这档开始进入有余量的区间。跑中等并发的应用服务、多个数据库实例、或者需要同时开测试环境和生产环境，才会用到这个配置。个人博客、单站点业务选这档基本是浪费。

**Pro（$169，8 核 16G / 5TB / 3Gbps）** 和 **Ultra（$338，12 核 32G / 10TB / 3Gbps）**：这两档的定位已经超出「一台 VPS」的范畴，更像是小型业务集群的替代方案。3Gbps 端口配上 5TB 起的流量，加上 Windows-ready 标注，适合需要跑 Windows 应用或单机承载较高并发的场景。个人用户和中小站点没有必要碰。

一个实际的决策顺序：先估算月流量峰值，卡到哪档就往上取一档；再看应用内存占用，MySQL 或多服务并行直接跳过 Nano；最后看要不要 Windows，需要就只能在 Pro 和 Ultra 里选。
